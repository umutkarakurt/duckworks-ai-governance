This folder contains the control records used to govern the **project itself**: who is involved, which assumptions drive conclusions, what must be delivered, and how completion is judged.

## Current artifacts

- `Duckworks_Project_Stakeholders_v1.0.md` — executive, first-line, second-line, third-line, specialist, system-owner, and affected-stakeholder roles.
- `Duckworks_Project_Assumptions_Register_v1.0.md` — controlled assumptions, status, materiality, rationale, and validation/evidence expectations.
- `Duckworks_Project_Required_Deliverables_v1.0.md` — dependency-based artifact register and planned capability set.
- `Duckworks_Project_Acceptance_Criteria_v1.0.md` — evidence-based project, artifact, traceability, independence, and system-release criteria.

## Governance principles demonstrated

**Assumptions are not facts.** Critical assumptions affecting intended purpose, human authority, safety, data, geography, legal role, or autonomy should trigger review when changed or invalidated.

**Evidence determines acceptance.** The acceptance model uses Pass, Pass with Action, Fail, and Not Applicable rather than subjective completion claims.

**Internal Audit remains independent.** Third-line assurance is not assigned ownership of first- or second-line controls.

**Traceability matters.** High/Critical systems should be traceable from inventory → impact → risk → treatment/decision → monitoring requirement.

This folder is especially useful to an auditor because it defines what evidence the rest of the repository is expected to produce.
